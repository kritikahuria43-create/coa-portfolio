What is Computer Organisation and Architecture?

Computer Architecture describes what a programmer sees: the instruction set, registers, addressing modes and data types. Computer Organisation describes how the hardware delivers that: control signals, buses, memory technology and the datapath. Together they explain how a program you write becomes electrical activity inside a machine.

Every topic is covered in the Learning tools page, from number systems and Boolean logic to cache memory, pipelining and input/output.

Why study COA?

Understand your computer

You learn what really happens between pressing a key and seeing the result on screen.

Write better programs

Knowing how memory, cache and the CPU work helps you write faster and more efficient code.

Base for other subjects

Operating systems, compilers, embedded systems, AI hardware and cloud computing all build on COA.

Useful for exams and interviews

COA questions are common in university exams, GATE, placements and technical interviews.

Frequently asked questions

Is COA the same as digital logic?

No. Digital logic is the foundation (gates, adders, flip-flops). COA uses those parts to explain how a complete computer is organised and how it runs programs.

Do I need to learn assembly language for COA?

You only need the basics: what an instruction looks like, how registers and memory are used and how addressing modes work. It makes the instruction cycle much easier to understand.

Which topics are the hardest?

Most students find cache mapping, pipelining hazards and floating-point representation hardest at first. Solved examples and practice problems help a lot, and you will find them on the Learning tools page.

How is COA useful for programmers?

It explains why some code is faster than other code, how memory is laid out and why cache-friendly loops run quickly.

What is the difference between 32-bit and 64-bit processors?

It refers to the natural word size: how many bits the registers, ALU and addresses handle at once. 64-bit processors can address far more memory and process larger numbers in one operation.

Begin with the notes on the Learning tools page, then use the interactive tools, try the CPU lab and finish with the quiz.

COA notes


Tap a topic to open it.


1. Basic structure and Von Neumann architecture
A computer has an input unit, output unit, memory, ALU and control unit. In the Von Neumann model, instructions and data share one memory and are carried over the same bus, which creates the "Von Neumann bottleneck". The Harvard model keeps separate memories and buses for instructions and data, allowing both to be fetched at once.


2. Registers and the CPU
Important registers: Program Counter (PC) holds the address of the next instruction, Instruction Register (IR) holds the current instruction, Memory Address Register (MAR) holds the address being accessed, Memory Data Register (MDR) holds the data read or written, and the Accumulator holds ALU results. The ALU performs arithmetic and logic, and the control unit generates timing signals.


3. Instruction cycle
Fetch: the PC value goes to the MAR, the instruction is read into the IR and the PC increases. Decode: the control unit works out the operation and operands. Execute: the ALU or memory performs the work. Store: the result is written back. Interrupts are checked at the end of each cycle.


4. Instruction formats and addressing modes
An instruction has an opcode and operand fields. Formats can use zero, one, two or three addresses. Addressing modes tell the CPU where to find the operand: immediate (value is in the instruction), direct (address is in the instruction), indirect (the address holds another address), register, register indirect, indexed, base register and relative.


5. Number representation
Unsigned binary, sign-magnitude, 1's complement and 2's complement are used for integers. 2's complement is standard because it has one zero and makes addition and subtraction use the same circuit. An n-bit 2's complement number ranges from -2n-1 to 2n-1-1. Floating-point numbers follow IEEE 754: a sign bit, an exponent and a mantissa (32 bits for single, 64 for double precision).


6. Boolean algebra and digital logic
Basic gates are AND, OR and NOT. NAND and NOR are universal gates because any circuit can be built from either one. De Morgan's laws: (A.B)' = A' + B' and (A+B)' = A'.B'. Combinational circuits (adders, multiplexers, decoders) depend only on current inputs. Sequential circuits (flip-flops, registers, counters) also depend on stored state.


7. Computer arithmetic
A half adder adds two bits; a full adder adds three bits including carry; a ripple-carry adder chains full adders, while a carry-lookahead adder is faster. Multiplication can use shift-and-add or Booth's algorithm, which handles signed numbers. Division uses restoring or non-restoring methods.


8. Control unit design
A hardwired control unit uses fixed logic circuits and is fast but hard to change. A microprogrammed control unit stores control signals as microinstructions in a control memory, which makes it flexible and easier to design but slower.


9. Memory hierarchy
From fastest to slowest: registers, cache, main memory (RAM), secondary storage. Higher levels are faster, smaller and costlier per bit. The hierarchy works because of locality of reference: programs reuse recent data (temporal locality) and nearby data (spatial locality). Average access time = hit rate x cache time + miss rate x memory time.


10. Cache memory
Cache mapping decides where a memory block can be placed: direct mapping (one fixed line), fully associative (any line) and set-associative (any line in one set). Replacement policies include LRU, FIFO and random. Write policies are write-through (update memory immediately) and write-back (update memory when the line is replaced).


11. Main memory and virtual memory
SRAM is fast and used for cache; DRAM is denser and used for main memory but needs refreshing. Virtual memory lets programs use more memory than is physically installed by dividing memory into pages and mapping them with a page table. The TLB caches recent translations. A page fault occurs when a needed page is not in RAM.


12. Input/Output organisation
Three methods transfer data: programmed I/O (the CPU waits and checks the device), interrupt-driven I/O (the device signals when ready) and DMA (a controller moves data between device and memory without the CPU). Buses are of three kinds: address, data and control.


13. Pipelining and hazards
Pipelining overlaps instruction stages (for example fetch, decode, execute, memory, write-back) so one instruction finishes every cycle once the pipeline is full. Speedup approaches the number of stages. Hazards slow it: structural (resource conflict), data (an instruction needs an earlier result) and control (branches). They are handled with stalls, forwarding and branch prediction.


14. RISC and CISC
RISC uses a small set of simple, fixed-length instructions, many registers and load/store memory access, which suits pipelining (examples: ARM, RISC-V). CISC uses many complex, variable-length instructions that can do more per instruction (example: x86).


15. Parallel processing and performance
Flynn's classification: SISD, SIMD, MISD and MIMD. Performance is measured by CPU time = instruction count x CPI x clock cycle time. MIPS and FLOPS describe speed, and Amdahl's law shows that the part of a program that cannot be improved limits total speedup.


16. Bus structure and interconnection
A bus is a shared set of wires that connects the CPU, memory and I/O. The address bus carries locations (its width sets the maximum memory), the data bus carries values (its width sets how much moves at once) and the control bus carries signals such as read, write and interrupt. Bus arbitration decides which device uses the bus when several request it. Examples include PCI Express, USB and SATA.


17. Instruction set architecture and assembly language
The ISA is the contract between software and hardware: it defines instructions, registers, data types, addressing modes and memory model. Assembly language gives readable names (such as ADD, LOAD, STORE, JMP) to machine instructions, and an assembler translates them into binary. Typical groups of instructions are data transfer, arithmetic and logic, shift, control transfer and input/output.


18. Secondary storage and RAID
Hard disks store data on rotating platters; access time = seek time + rotational latency + transfer time. SSDs use flash memory with no moving parts, so they are faster and quieter. RAID combines several disks for speed or safety: RAID 0 stripes data (fast, no protection), RAID 1 mirrors it (safe, costly), and RAID 5 spreads data with parity so one disk can fail.


19. Number systems in depth
Positional notation: each digit is multiplied by the base raised to its position. To convert a decimal fraction, multiply the fraction part by the new base repeatedly and read the integer parts from top to bottom (0.625 = 0.101 in binary). BCD stores each decimal digit in 4 bits (45 is 0100 0101). Gray code changes only one bit between consecutive values (000, 001, 011, 010, 110, 111, 101, 100), which avoids errors in position encoders. Hexadecimal is used because one hex digit equals exactly four bits.


20. Signed number representations compared
For 4 bits: sign-magnitude ranges from -7 to +7 and has two zeros; 1's complement also ranges from -7 to +7 with two zeros; 2's complement ranges from -8 to +7 with one zero. Overflow in 2's complement happens when adding two positive numbers gives a negative result or adding two negative numbers gives a positive result. It is detected when the carry into the sign bit differs from the carry out of the sign bit.


21. IEEE 754 worked example
Convert 5.75 to single precision. 5.75 = 101.11 in binary = 1.0111 x 2^2. Sign = 0. Exponent = 2 + 127 = 129 = 10000001. Mantissa = 0111 followed by zeros to make 23 bits. Result: 0 10000001 01110000000000000000000, which is 40B80000 in hexadecimal. Special cases: exponent all 0s means zero or denormal numbers, exponent all 1s means infinity or NaN. Double precision uses 1 sign bit, 11 exponent bits (bias 1023) and 52 mantissa bits.


22. Booth's multiplication algorithm
Booth's algorithm multiplies signed 2's complement numbers. It looks at the last bit of the multiplier (Q0) and an extra bit (Q-1): pair 00 or 11 means only shift right; pair 01 means add the multiplicand then shift; pair 10 means subtract the multiplicand then shift. The shift is an arithmetic shift, so the sign is kept. It is efficient when the multiplier has long runs of 1s because a run is replaced by one subtraction and one addition.


23. Combinational and sequential building blocks
A half adder has Sum = A XOR B and Carry = A AND B. A full adder has Sum = A XOR B XOR Cin and Cout = AB + Cin(A XOR B). A multiplexer selects one of 2^n inputs using n select lines. A decoder turns an n-bit input into one of 2^n outputs. Flip-flops (SR, D, JK, T) store one bit; a D flip-flop copies its input on the clock edge. A register is a group of D flip-flops, and a counter is a register that steps through a sequence.


24. Register transfer language and micro-operations
Register transfer is written like R2 ← R1. The instruction fetch in micro-operations is: T0: MAR ← PC; T1: MDR ← M[MAR], PC ← PC + 1; T2: IR ← MDR; T3: decode the opcode. Micro-operations are of four kinds: register transfer, arithmetic (add, subtract, increment), logic (AND, OR, XOR, complement) and shift (logical, arithmetic, circular).


25. Addressing modes with examples
Take an instruction LOAD 500: 
Immediate: ACC = 500 (the value is in the instruction).
Direct: ACC = M[500].
Indirect: ACC = M[M[500]].
Register: the operand is in a named register.
Register indirect: the register holds the memory address.
Indexed: effective address = 500 + index register, good for arrays.
Base register: effective address = base + offset, good for relocating programs.
Relative: effective address = PC + offset, used for branches.


26. Cache address breakdown
A memory address is split into tag, index and block offset. Offset bits = log2(block size). For a direct-mapped cache, index bits = log2(number of lines). The remaining bits are the tag. Example: 32-bit address, 16 KB cache, 64-byte blocks, direct-mapped: 256 lines, so 6 offset bits, 8 index bits and 18 tag bits. In a set-associative cache the index selects a set and the tag is compared with every line in that set.


27. Virtual memory and paging in detail
A virtual address is split into a page number and an offset. The page table maps each page number to a frame number, and each entry also has a valid bit, a dirty bit and protection bits. With 4 KB pages the offset is 12 bits. If a page is not in memory a page fault occurs and the operating system loads it, replacing another page using FIFO, LRU or Optimal. If a system spends more time swapping than executing it is thrashing. FIFO can show Belady's anomaly, where adding frames increases page faults.


28. Interrupt handling steps
1) A device raises an interrupt. 2) The CPU finishes the current instruction. 3) It saves the PC and flags. 4) It finds the source (vectored interrupts give the address directly, polled interrupts check each device). 5) It jumps to the interrupt service routine (ISR). 6) The ISR runs and handles the event. 7) The CPU restores the saved state and returns to the program. Interrupts can be masked (maskable) or not (non-maskable) and can have priorities. Exceptions or traps are caused by the program itself, such as divide by zero.


29. The five-stage pipeline in detail
Stages: IF (instruction fetch), ID (decode and read registers), EX (execute), MEM (memory access) and WB (write back). Four instructions in an ideal pipeline overlap like this:
Cycle 1: I1 IF
Cycle 2: I1 ID, I2 IF
Cycle 3: I1 EX, I2 ID, I3 IF
Cycle 4: I1 MEM, I2 EX, I3 ID, I4 IF
Cycle 5: I1 WB, I2 MEM, I3 EX, I4 ID
Hazards are reduced by forwarding, stalls (bubbles), branch prediction (1-bit and 2-bit predictors) and delayed branches. Superscalar processors issue several instructions per cycle, and out-of-order execution lets later independent instructions run while earlier ones wait.


30. Parallel processing and multiprocessors
Parallelism exists at many levels: instruction level (pipelining, superscalar), data level (SIMD and vector units, GPUs), thread level (multithreading, multi-core) and process level (clusters). Multiprocessors may use shared memory (all CPUs see one address space) or distributed memory (each CPU has its own memory and they exchange messages). With private caches the cache coherence problem appears; the MESI protocol keeps each cache line in one of four states: Modified, Exclusive, Shared or Invalid.


31. Error detection and correction
A parity bit makes the number of 1s even (even parity) or odd (odd parity) and detects any single-bit error. Checksums and CRC detect errors in blocks of data. Hamming code adds r parity bits to m data bits where 2^r ≥ m + r + 1, and can correct a single-bit error and detect a double-bit error with an extra parity bit. ECC memory in servers uses these ideas.


32. Memory organisation and interleaving
A memory chip is a 2D array of cells selected by row and column addresses. DRAM cells need refreshing. Interleaving spreads consecutive addresses over several memory banks so they can be accessed at the same time, increasing bandwidth. SDRAM works with the system clock, and DDR memory transfers data on both the rising and falling clock edges, doubling the transfer rate per clock.


33. Endianness and alignment
Store the 32-bit value 0x12345678 at address 100. A big-endian machine stores the bytes 12, 34, 56, 78 at addresses 100 to 103. A little-endian machine stores 78, 56, 34, 12. x86 and most ARM systems are little-endian. Aligned access means a 4-byte word starts at an address divisible by 4, which is faster on most hardware.


34. A small assembly example
High-level statement: c = a + b. In a simple register machine this becomes:
LOAD R1, a
LOAD R2, b
ADD R3, R1, R2
STORE c, R3
A loop that sums an array uses a counter, an index register and a conditional branch (for example BNE) that jumps back until the counter reaches zero. Each assembly instruction maps to one machine instruction with an opcode and operand fields.



35. Microprogrammed control in detail
Each machine instruction maps to a routine of microinstructions held in control memory. The control address register picks the next microinstruction, a sequencer handles branches, and horizontal formats use one bit per signal (wide but fast) while vertical formats encode signals (narrow but slower). Nanoprogramming adds a second level of storage to save space.


36. Memory-mapped and isolated I/O
In memory-mapped I/O, device registers share the address space with memory, so ordinary LOAD and STORE instructions control devices. In isolated I/O, a separate address space and special IN and OUT instructions are used. Memory-mapped I/O is simpler for programmers but uses up some memory addresses.


37. Branch prediction
A 1-bit predictor remembers the last outcome of a branch. A 2-bit saturating counter changes its guess only after two wrong predictions, so a loop branch is mispredicted just once per loop exit. A branch target buffer stores target addresses to avoid fetch delay.


38. Superscalar, VLIW and multithreading
Superscalar CPUs find independent instructions at run time and issue several per cycle. VLIW moves that job to the compiler, which packs instructions into long words. Simultaneous multithreading lets one core run instructions from several threads to keep its units busy.


39. GPU architecture
A GPU has thousands of simple cores grouped into streaming multiprocessors that run the same instruction on many data items (SIMT). It trades single-thread speed for very high throughput, which suits graphics, simulation and neural networks.


40. Power and energy in processors
Dynamic power is proportional to capacitance x voltage squared x frequency. Lowering voltage helps most, which is why designers use many slower cores, clock gating and dynamic voltage and frequency scaling instead of one very fast core.


Solved numerical problems


Try each problem yourself first, then open the solution.
Problem 1. Convert 156 to binary, octal and hexadecimal.
156 = 128 + 16 + 8 + 4, so the binary is 10011100. Group in threes from the right: 010 011 100 gives octal 234. Group in fours: 1001 1100 gives hexadecimal 9C.


Problem 2. Compute 9 - 5 using 8-bit 2's complement.
9 = 00001001. 5 = 00000101, so -5 = 11111011 (invert and add 1). Add: 00001001 + 11111011 = 1 00000100. Discard the carry out, giving 00000100 = 4.


Problem 3. A program has 2 x 10^9 instructions, an average CPI of 1.5 and a 3 GHz clock. Find the CPU time.
CPU time = (instruction count x CPI) / clock rate = (2 x 10^9 x 1.5) / (3 x 10^9) = 1 second.


Problem 4. Find the average CPI: 50% ALU (CPI 1), 30% load/store (CPI 2), 20% branch (CPI 3).
Average CPI = 0.5 x 1 + 0.3 x 2 + 0.2 x 3 = 0.5 + 0.6 + 0.6 = 1.7.


Problem 5. Hit time 2 ns, miss rate 4%, miss penalty 80 ns. Find the AMAT.
AMAT = hit time + miss rate x miss penalty = 2 + 0.04 x 80 = 5.2 ns.


Problem 6. A 5-stage pipeline runs 100 instructions with a 2 ns clock. Find the speedup over a non-pipelined machine.
Pipelined: (5 + 100 - 1) = 104 cycles = 208 ns. Non-pipelined: 100 x 5 = 500 cycles = 1000 ns. Speedup = 1000 / 208 = about 4.81.


Problem 7. 32-bit address, 32 KB cache, 64-byte blocks, 4-way set associative. Find the tag, index and offset bits.
Lines = 32768 / 64 = 512. Sets = 512 / 4 = 128. Offset = 6 bits, index = 7 bits, tag = 32 - 6 - 7 = 19 bits.


Problem 8. How many 4K x 8 chips are needed for a 16K x 16 memory, and how many address lines?
Chips = (16K / 4K) x (16 / 8) = 4 x 2 = 8 chips. 16K = 2^14, so 14 address lines.


Problem 9. 32-bit virtual addresses and 4 KB pages: how many page table entries and how big is the table if each entry is 4 bytes?
Offset = 12 bits, so the page number = 20 bits and there are 2^20 (about 1 million) entries. Size = 2^20 x 4 bytes = 4 MB.


Problem 10. 40% of a program is made 10 times faster. Find the overall speedup.
Speedup = 1 / ((1 - 0.4) + 0.4 / 10) = 1 / (0.6 + 0.04) = 1.5625.


Problem 11. Seek time 5 ms, 7200 rpm, transfer time 0.1 ms. Find the average disk access time.
One rotation = 60 / 7200 = 8.33 ms, so average rotational latency = 4.17 ms. Access time = 5 + 4.17 + 0.1 = about 9.27 ms.


Problem 12. Decode the IEEE 754 number 0 10000010 10100000000000000000000.
Sign 0 (positive). Exponent 130 - 127 = 3. Mantissa 1.101 in binary = 1.625. Value = 1.625 x 2^3 = 13.



Problem 13. A 16 KB, 2-way set-associative cache has 32-byte blocks. How many sets are there?
Lines = 16384 / 32 = 512. Sets = 512 / 2 = 256. Index = 8 bits, offset = 5 bits.


Problem 14. A pipeline has 4 stages of 10 ns and 6 stall cycles over 50 instructions. Find the total time.
Cycles = 4 + 50 - 1 + 6 = 59. Time = 59 x 10 = 590 ns.


Problem 15. A processor runs at 2.5 GHz with CPI 1.2. What is its MIPS rating?
MIPS = clock rate / (CPI x 10^6) = 2500 / 1.2 = about 2083 MIPS.


Problem 16. Encode -6.5 in IEEE 754 single precision.
6.5 = 110.1 = 1.101 x 2^2. Sign = 1, exponent = 129 = 10000001, mantissa = 101 followed by zeros. Result: 1 10000001 10100000000000000000000 = C0D00000.

Viva and exam questions


Short answers to questions that are often asked.


Q1. What is the difference between computer organisation and architecture?
Architecture is the set of attributes visible to the programmer (instruction set, addressing modes, data types). Organisation is how those features are implemented in hardware (control signals, interfaces, memory technology).


Q2. What is the Von Neumann bottleneck?
Because instructions and data share one bus and memory, the CPU cannot fetch both at the same time, which limits performance.


Q3. Why is 2's complement used?
It has a single representation of zero, and addition and subtraction can use the same hardware.


Q4. Why are NAND and NOR called universal gates?
Any Boolean function can be built using only NAND gates or only NOR gates.


Q5. What does the program counter do?
It holds the address of the next instruction to be fetched and increases after each fetch.


Q6. What is the difference between SRAM and DRAM?
SRAM uses flip-flops, is faster, costlier and needs no refresh, so it is used for cache. DRAM uses capacitors, is slower, cheaper and denser, and needs periodic refresh, so it is used for main memory.


Q7. What is locality of reference?
Programs tend to access the same or nearby memory locations repeatedly (temporal and spatial locality), which is why caches work.


Q8. Name the types of cache mapping.
Direct mapping, fully associative mapping and set-associative mapping.


Q9. What is a page fault?
It happens when the CPU needs a page that is not in main memory, so the operating system loads it from disk.


Q10. What is DMA and why is it useful?
DMA lets a controller transfer data between a device and memory without the CPU, freeing the CPU for other work.


Q11. What are the three types of pipeline hazards?
Structural hazards (resource conflict), data hazards (dependency on a previous result) and control hazards (branches).


Q12. What is forwarding?
Passing a result directly from one pipeline stage to another that needs it, without waiting for it to be written back, to reduce data hazard stalls.


Q13. Difference between RISC and CISC?
RISC has few, simple, fixed-length instructions and relies on registers and load/store. CISC has many complex, variable-length instructions that can do more in one instruction.


Q14. What is the difference between hardwired and microprogrammed control?
Hardwired control uses fixed logic circuits and is fast but inflexible. Microprogrammed control stores control signals in memory, so it is easier to modify but slower.


Q15. What does Amdahl's law tell us?
The overall speedup from improving one part of a system is limited by the fraction of time that part is actually used.

What does it do?


Real hardware hides what happens inside it. My stimulator simulates the behaviour of a processor and its memory in software and lets you see registers, memory and signals change after every step. Long answer questions with outlines


1. Explain the instruction cycle with a neat diagram.
Draw fetch, decode, execute and store as boxes in a loop. Explain: PC to MAR, memory read into MDR then IR, PC incremented, control unit decodes the opcode, operands are fetched, ALU or memory performs the operation, the result is stored, and interrupts are checked at the end.


2. Compare direct, fully associative and set-associative cache mapping.
Direct: each block has exactly one line (index = block mod lines), simple and fast but conflict misses. Fully associative: a block can go in any line, no conflicts but costly comparison of all tags. Set-associative: a block maps to one set and can go in any line of it, a balance. Show the tag, index and offset split.


3. What is pipelining? Explain its hazards.
Define pipelining as overlapping stages (IF, ID, EX, MEM, WB). Show the timing diagram. Explain structural, data (RAW, WAR, WAW) and control hazards with one example each and the fixes: stalls, forwarding, branch prediction.


4. Explain DMA with a block diagram.
Draw CPU, memory, DMA controller and device on a bus. Steps: CPU programs the DMA controller with address and count, DMA takes bus control, transfers data directly, sends an interrupt when done. Mention burst mode and cycle stealing.


5. Explain virtual memory and paging.
Define virtual and physical addresses, pages and frames. Show the address split into page number and offset, the page table lookup, TLB, page fault handling and page replacement (FIFO, LRU). Mention thrashing.


6. Compare RISC and CISC.
Use a table: instruction count and complexity, instruction length, addressing modes, registers, control unit, pipelining ease, code size, examples (ARM, RISC-V vs x86).


7. Explain Booth's algorithm with an example.
State the rules for the pairs (Q0, Q-1): 00 and 11 shift, 01 add, 10 subtract. Show a table of A, Q, Q-1 and the step count for a small example such as 3 x (-4), and the final product.


8. Explain the memory hierarchy and locality of reference.
Draw the pyramid from registers to disk. Explain speed, size and cost trends, temporal and spatial locality, and give the AMAT formula with a numerical example.


True or false


Decide first, then open the answer.
1. Cache is faster than registers.
False. Registers are inside the CPU and are the fastest memory.


2. 2's complement has only one representation of zero.
True.


3. In DMA the CPU moves every byte of data.
False. The DMA controller moves the data.


4. The program counter holds the current instruction.
False. It holds the address of the next instruction.


5. NAND is a universal gate.
True.


6. Pipelining reduces the time taken by a single instruction.
False. It improves throughput; one instruction still takes about the same time.


7. Virtual memory lets a program be larger than the installed RAM.
True.


8. Little-endian stores the most significant byte at the lowest address.
False. It stores the least significant byte first.


9. SRAM needs periodic refreshing.
False. DRAM needs refreshing.


10. Harvard architecture has separate memories for instructions and data.
True.

John von Neumann described a design where instructions and data share one memory. This is the Von Neumann architecture.


1947: The transistor
Invented at Bell Labs, it replaced vacuum tubes and made computers smaller and more reliable.


1958: Integrated circuit
Jack Kilby built the first integrated circuit, putting several components on one piece of semiconductor.


1971: First microprocessor
Intel released the 4004, a complete CPU on a single chip.


1980s: RISC ideas
Research at Berkeley and Stanford led to RISC designs. ARM processors also began in this decade.


2000s: Multi-core processors
Because clock speeds could not keep rising without too much heat, designers added more cores instead.


2010s: GPUs for AI and RISC-V
GPUs became the main hardware for training neural networks, and the open RISC-V instruction set began to spread.




Moore's law and the power wall


In 1965 Gordon Moore observed that the number of transistors on a chip doubles roughly every two years. This drove decades of faster computers. Today, shrinking transistors is harder and chips produce too much heat at high clock speeds, which is known as the power wall. That is why modern design focuses on parallelism and efficiency.


Where processor design is heading


Multi-core and many-core
More cores working in parallel rather than one very fast core.
GPUs and AI accelerators
Chips built for matrix maths speed up machine learning and graphics.
ARM and RISC-V
Energy-efficient RISC designs power phones, laptops and servers.
Energy efficiency
Performance per watt is now as important as raw speed.
Cloud and data centres
Huge pools of processors shared over the internet, as in Microsoft Azure.
Quantum computing
A very different model of computation, still at an early research stage.

Evolution of memory


Magnetic core memory (1950s)
Tiny magnetic rings stored each bit and could be read even after power loss.
Semiconductor memory (1970)
Chips such as the Intel 1103 DRAM made memory small, cheap and fast.
Cache memory (1980s and 1990s)
On-chip SRAM caches hid the slow speed of main memory.
Solid-state drives (2000s)
Flash storage replaced many hard disks with a faster, silent alternative.
High-bandwidth memory (2010s)
Stacked memory placed close to GPUs and accelerators for AI workloads.


Lessons from history


  • Every generation became smaller, faster, cheaper and more power-efficient
  • Good ideas such as the stored program lasted for decades
  • Bottlenecks move: first processor speed, then memory speed, now power and heat
  • Open designs such as RISC-V allow more people to build processors

Myths about computers


Myth: More GHz always means a faster computer.
Speed also depends on instructions per cycle, cache, memory speed and the number of cores. A lower clock with a better design can be faster.


Myth: More RAM always makes a computer faster.
Extra RAM helps only if you were running out of memory. After that it makes no difference.


Myth: 64-bit means twice as fast as 32-bit.
It means wider registers and a much larger address space. Some programs benefit, but it is not simply twice as fast.


Myth: Computers think.
A computer just follows instructions extremely fast. It does exactly what the program says.


Myth: Deleting a file removes it immediately from the disk.
Usually only the entry is removed and the data stays until it is overwritten.


Myth: Binary is only for programmers.
Binary is how all digital hardware works, because transistors have two states: on and off.


Did you know? The Intel 4004 of 1971 had about 2,300 transistors. A modern processor has tens of billions.

Technical interview questions on COA


What happens when you press a key on the keyboard?
The keyboard controller sends a signal, which raises an interrupt. The CPU saves its state and runs the keyboard interrupt service routine, which reads the key code and places it in a buffer. The operating system then passes it to the program that is waiting for input.


Why is cache faster than main memory?
Cache is built from SRAM, is much smaller and sits close to or inside the CPU, so it has lower access time. It works because of locality of reference.


Why is a row-by-row loop over a 2D array often faster than column-by-column?
Arrays are stored row by row, so row access uses consecutive addresses and makes good use of cache blocks (spatial locality).


What is the difference between a process and a thread from a hardware view?
Threads of one process share memory and can run on different cores, while processes have separate address spaces managed through virtual memory.


What is a context switch?
The CPU saves the registers and PC of the running task and loads those of another task so several tasks share the CPU.


What is instruction-level parallelism?
Running several instructions at the same time inside one core using pipelining, superscalar issue and out-of-order execution.


Why did processors move from higher clock speeds to more cores?
Higher clock speeds caused too much heat and power use, so designers added cores to gain speed within a safe power limit.


What is the role of the stack in a program?
It stores return addresses, parameters and local variables for function calls, managed with a stack pointer register.
